## Design Specificity Verdict

**设计判断：内容高度特定，视觉结构仍有明显的通用管理后台成分。**

生命周期、不可变摘要、稳定 Service Account 主体、匿名读取双层策略及晋升/复制语义让它不可能被简单替换成普通 CRUD 后台；真正的产品性格来自这些对象和决策边界。不过，页面结构仍大量依赖“PageHeader + MetricStrip + Card + Table”，Public Browse 的渐变 Hero、发光装饰和 eyebrow 又落回常见 SaaS 展示套路。产品特异性主要由内容承担，构图还没有完全兑现 “The Verified Control Plane”。

**Deterministic scan：** detect.mjs --json console/src 返回 []，0 条机械规则问题。这说明已清除 transition-all 等显式反模式，但 detector 无法发现 11 个同级标签、工作流分裂、低对比微型文本和反馈语义不一致。

**Visual overlays：** 浏览器禁止可变脚本注入，未生成可信的用户可见 overlay。替代证据来自 CLI detector、DOM snapshot、桌面/移动 viewport、横向溢出和 console 结果。

## Overall Impression

这是一个已经“能工作且知道自己是什么”的 Console，不再是拼装式原型。最大机会不是增加视觉效果，而是把高风险操作员任务从多个页面和大量同权信息中抽出来，形成清晰、可验证的任务路径。

## What’s Working

- **领域与安全边界表达准确。** Public Browse 明确“公开只读”，Service Accounts 清楚区分稳定主体与可轮换凭据，危险操作说明实际后果。
- **响应式与状态基线可靠。** 1440×900、390×844 的 Public Browse、OCI detail 和 Login 均无页面级横向溢出，console 为 0 error/0 warning；Loading/Error/Empty 已形成共享语言。
- **真实任务证据被保留。** 坐标、摘要、客户端命令、last used、过期时间、request ID、审计与生命周期状态没有被视觉简化掉。

## Priority Issues

### [P1] 关键元数据被压进低对比微型文本

- **Why it matters：** 全项目约有 132 处 text-[10px] / text-[11px]。其中不少搭配 text-zinc-600/700，出现在访问决策、扫描配置、诊断、凭据用途和错误细节中，违反 DESIGN 的 12px operational floor；低视力、200% 缩放和疲劳操作场景会直接丢失信息。
- **Fix：** 建立 label / technical / muted 三种真实 token；把必需说明提升到至少 12px 且满足 4.5:1，只允许品牌副标或非必要装饰保留 10/11px。
- **Suggested command：** $impeccable typeset console/src

### [P1] Repository Detail 把最多 11 个任务当成同级标签页

- **Why it matters：** 制品、发布、授权、保留、扫描、安全、容量、晋升/复制、任务、墓碑和设置同时竞争。操作员需要记住概念位置，移动端还要横向寻找；这已经超过工作记忆的合理范围。
- **Fix：** 保留深链合同，但把信息架构收敛为 3–4 个任务组，例如“制品与发布 / 治理与安全 / 运行与分发 / 设置”，二级任务在组内呈现。
- **Suggested command：** $impeccable distill console/src/pages/RepositoryDetail.tsx

### [P1] 复制与局部操作反馈仍有 11 套实现

- **Why it matters：** 共享 CopyableValue 已有成功播报和失败提示，但 PublicBrowse、RepositoryUsageGuides、Go/npm/PyPI/OCI detail 等仍存在静默 catch 或只处理 Promise success。相同动作在不同协议页面表现不同，会损害控制台的可信感。
- **Fix：** 收敛为一个 clipboard action primitive/hook，统一成功、失败、读屏播报、定时器清理和不安全上下文降级。
- **Suggested command：** $impeccable harden console/src

### [P2] Service Account 的完整轮换任务仍跨页面断裂

- **Why it matters：** 当前页面很好地解释稳定主体和 Token 重叠，但操作员仍需复制 principal，再去 Access Control 找授权，随后去 Operations/Audits 验证使用情况。轮换本身可完成，验证闭环需要人工记忆。
- **Fix：** 在账号详情内提供“查看 Repository Grants”“查看最近使用/审计”“轮换检查清单”等上下文入口，不复制后台数据，只链接到已有真实视图。
- **Suggested command：** $impeccable clarify console/src/pages/ServiceAccounts.tsx

### [P2] 移动端公开制品详情仍以桌面表格为主要载体

- **Why it matters：** 页面本身没有溢出，但 390px OCI detail 仍包含多列表格和内部横向滚动。用户能访问，却很难单手比较版本、摘要和操作。
- **Fix：** 小屏改为按制品分组的摘要卡/Disclosure，保留表格作为中大屏呈现；主要操作和选中版本始终可见。
- **Suggested command：** $impeccable adapt console/src/pages/PublicBrowse.tsx

## Cognitive Load

失败 3/8，属于中等负荷：

- **Single focus：失败。** Repository Detail 同时呈现过多同级任务入口。
- **Minimal choices：失败。** 最多 11 个标签页、Public Browse 6 个并列格式筛选。
- **Progressive disclosure：失败。** 生命周期治理、运行和配置任务在第一层一次性暴露。
- Grouping、visual hierarchy、one thing at a time、working-memory support 和基础 chunking 在多数独立页面表现合格。

## Emotional Journey

- **进入：** Public Browse 的只读边界和管理登录分离很安心。
- **理解：** 真实格式、仓库类型与客户端命令让用户迅速建立信任。
- **低谷：** 进入 Repository Detail 后，任务入口密度突然升高；微型低对比文本迫使用户放慢阅读。
- **高风险时刻：** 删除、禁用和吊销文案能够说明后果，是明显优势。
- **结束：** 成功反馈并不一致；尤其复制配置失败时，部分页面没有明确收尾，削弱“已完成且可验证”的感觉。

## Persona Red Flags

**Alex（高频管理员）**

- 全局搜索、筛选和 URL 深链有效。
- 没有快捷键或批量入口；Repository Detail 需要在最多 11 个标签间重复切换。
- 同类 copy 操作反馈不一致，无法形成稳定肌肉记忆。

**Sam（键盘/读屏/低视力用户）**

- 焦点样式、语义化 Loading、Ant Design 控件和危险确认是可靠基础。
- 10/11px + zinc-600/700 的必要元数据难以读取。
- 移动/高倍缩放下的内部滚动表格增加线性浏览成本；部分复制成功或失败没有统一 live announcement。

**Lin（平台制品管理员）**

- 能理解稳定机器主体、凭据轮换和 Repository Grant 的合同。
- 完成一次零停机轮换仍要在 Service Accounts、Access Control、Operations 和 Audits 间跳转。
- 缺少“新 Token 已部署—已观察使用—旧 Token 可吊销”的可验证任务闭环。

## Minor Observations

- Public Browse 的渐变、发光球和 eyebrow 与 DESIGN 中克制的 Operate 方向存在轻微漂移。
- Dashboard 的浏览器本地趋势虽有免责声明，但视觉权重接近权威后端指标，应持续避免误读。
- 主导航 12 项已按运行/治理/管理分组，桌面可接受；移动 Drawer 中仍应关注扫描长度。
- Detector 0 findings 是代码规范信号，不等同于设计问题为零。

## Questions to Consider

- 如果 Repository Detail 只能保留四个一级入口，哪四个最符合操作员真实任务？
- Service Account 页面能否从“凭据管理页”升级为“轮换完成与验证中心”？
- Public Browse 应该像一个对外展示入口，还是像 Console 的匿名只读工作区？
