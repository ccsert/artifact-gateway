## Design Specificity Verdict

**内容与构图都已具备产品特异性。** 不可变摘要、稳定服务账号主体、匿名读取边界、晋升与复制语义仍是性格来源；v2 去掉了青色实底按钮和彩色胶囊，状态改为“点 + 文字”，表格不再强制大写，整体从通用后台转向克制的工程控制台。剩余的通用成分是几乎每个列表页都以同一组“指标条 + 筛选卡 + 表格”开场，指标条对少量数据的页面（分组 1 个、服务账号 1 个）信息量偏低。

## Priority Issues

### [P2] 扩展主题包 Aerok 未达到 AA

- **Why it matters：** Aerok Light 的三级文字、成功、警告、信息色衬在页面底色上只有 2.5–3.8:1；Aerok Dark 的危险色衬在卡片上为 4.23:1。选择该主题的用户读状态文字会吃力。
- **Fix：** 主题包负责人调整这 5 个色值；调整后把 `themeContrast.test.ts` 的覆盖范围从 Gateway 主题扩展到全部内置主题。
- **Owner：** 主题包维护者（品牌色值不应由 Console 重构单方面修改）。

### [P2] 服务账号轮换仍跨页面断裂（上次遗留）

- **Why it matters：** 轮换的“新凭据已部署 → 已观察到使用 → 可以吊销旧凭据”需要在服务账号、访问控制和审计之间手动跳转。
- **Fix：** 在服务账号详情加“查看授权”“查看最近审计”的上下文链接（带好主体筛选的 URL），复用已有视图，不复制数据。`useUrlFilters` 已经让这类深链成为可能。

### [P2] 少量数据的页面指标条信息量偏低

- **Why it matters：** 分组、服务账号页面的指标条在只有一两条记录时只是在重复表格内容，却占据首屏最显眼的位置。
- **Fix：** `ListPage` 增加“记录数少于阈值时不显示指标条”的约定，或把指标收进表格标题行。

### [P2] 视觉基线只覆盖桌面宽度

- **Why it matters：** 390px 下的回归只能靠 E2E 的几何断言发现，看不到视觉层面的退化。
- **Fix：** 在 `pages.visual.spec.ts` 为登录、公开浏览、仓库详情增加 390px 的 surfaces。

## Cognitive Load

失败 1/8，属于低负荷：

- **Progressive disclosure：部分失败。** 列表页的指标条在数据很少时仍然先于主要任务出现。
- Single focus、minimal choices（行操作收进菜单）、grouping（仓库详情 4 组）、visual hierarchy、one thing at a time、working-memory support、chunking 均合格。

## Minor Observations

- 全页截图中侧栏背景只覆盖首屏高度（fixed 定位），属截图形态，不影响真实使用。
- `command-palette` 截图背后的总览环形图偶发位置抖动，会让视觉基线不稳定，值得单独修复。
- 公开浏览的品牌插画与 Console 主体风格一致性尚可，登录页已去除内部 API 命名。
