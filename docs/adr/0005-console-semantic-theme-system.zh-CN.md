# Console 主题统一使用已解析语义投影

[English](0005-console-semantic-theme-system.md) · [文档索引](../README.zh-CN.md)

状态：已接受

## 背景

Artifact Gateway Console 内置四套 Theme Package，并能从服务端加载更多主题包。主题包只
包含受约束的 Ant Design Seed/Alias Token 子集。此前运行时通过多条互不统一的路径投影
主题：

- Ant Design 接收一份 `ThemeConfig`；
- 全局 CSS 接收一组扁平的 `--ag-*` 变量；
- Gateway Dark 与 Gateway Light 另有一份兼容变量表；
- `styles.css` 又维护明暗首屏调色板和页面级颜色字面量。

因此界面虽然“能换颜色”，却不是一套主题系统。主强调色还同时承担文本选择、普通章节
图标、中性空状态、装饰光晕和通用生命周期元数据。切换主题会改变过多无关信号，而只修
CSS 又很容易与 Ant Design 组件漂移。

现有设计系统已经规定信号色必须稀缺。实现需要一份可执行、可测试、可扩展的契约，同时
不能把任意 CSS 配置开放给服务端主题包。

## 比较过的方案

### 1. 自定义 CSS 直接消费 Ant Design CSS 变量

该方案少一层投影，但会把产品 UI 绑定到 Ant Design 的变量命名与生成行为；它也无法表达
文本选择、Shell Chrome、导航位置或品牌资产等产品角色，更无法提供完整的 React 启动前
首屏调色板。

### 2. 每个 Theme Package 携带完整 CSS 变量表

该方案控制力最大，但会制造两套颜色系统、扩大不可信配置面、提高 Schema 演进成本，并
允许主题意外修改几何或运维语义。

### 3. Console 内统一解析为语义投影

服务端主题包继续作为受约束的颜色输入。Console 先通过对应 Ant Design 算法解析完整
Token，再投影为带类型的产品语义角色。Ant Design 组件 Token 与自定义 CSS 变量都从这些
角色生成，并由一个运行时在同一次渲染事务中应用。

该方案多一层内部模块，但这层正是另外两种方案缺少的产品词汇，因此采用此方案。

## 决策

Theme Package schema v1 继续作为外部契约，只接受稳定的颜色 Seed/Alias Token，不能修改
字体、密度、间距、组件几何或任意 CSS。本次不需要 API 迁移。

Console 维护一个 `ResolvedConsoleTheme` 深模块，对外形状如下：

```text
ConsoleTheme 主题包
        │
        ▼
Ant Design 明暗算法 + 主题包显式 Alias
        │
        ▼
ResolvedConsoleTheme
  ├─ antDesign: ThemeConfig
  ├─ token: 已解析 Ant Design 全局 Token
  ├─ roles: 带类型的 Console 语义角色
  └─ cssVariables: 完整语义 CSS 投影
        │
        ├─ ConfigProvider
        └─ 在同一次主题提交中写入 document root
```

解析器是纯函数；运行时应用函数是唯一能向文档写入主题变量的代码。主题预览消费已解析
角色，不再自行拼装调色板。内置主题的视觉兼容使用带类型的角色覆盖，而不是无结构 CSS
变量表。

CSS 首屏调色板只用于站点设置加载期间避免无主题闪烁。它使用相同语义变量名、覆盖明暗
模式，并在运行时被完整投影覆盖；它不是第五套主题行为来源。

## 语义角色契约

| 家族 | 目的 | 示例 |
| --- | --- | --- |
| Surface | 不携带状态含义的层级与交互 | 画布、容器、半透明容器、浮层、悬停、禁用、Shell Chrome |
| Content | 可读信息层级 | 强文本、正文、次级、三级、禁用、主操作上文字、品牌上文字 |
| Border | 结构与焦点 | 默认、弱边界、行分隔、强边界、焦点 |
| Action | 当前决策面的主操作 | 主色、悬停、按下、弱背景、阴影 |
| Link | 可导航文本与可信深链接 | 默认、悬停、按下 |
| Focus | 与具体组件实现无关的键盘位置 | 焦点环 |
| Selection | 浏览器原生文本选择 | 中性背景与正常可读文字 |
| Navigation | 当前应用位置 | 指示条、选中背景、选中文字 |
| Status | 有功能含义的运维状态 | 成功、警告、危险、信息及其前景、弱背景、边框 |
| Visualization | 不表达运维状态的数据编码 | 稳定分类色板、趋势主/次色、未知分类回退色 |
| Identity | 只服务产品/站点标志 | 渐变色阶、前景、轮廓、光晕 |
| Effect | 非颜色结构 | 结构/浮层阴影、滚动条、圆角 |

组件几何继续由 Console 固定。组件颜色必须来自语义角色：普通 Hover 使用中性色，选中导航
使用 Navigation，输入焦点使用 Focus，状态组件只能使用对应 Status 家族。

## 强调色预算

主强调色只允许用于：

- 一个决策面中的唯一主操作；
- 当前导航或 Tab 位置；
- 键盘焦点；
- 可信文本链接和可操作生命周期入口；
- 真正的产品/站点标志。

主强调色禁止用于：

- 浏览器原生文本选择；
- 卡片、表格行和次级控件的普通 Hover；
- 通用章节图标、中性 Badge、空状态或卡片边框；
- 禁用控件；
- 大面积装饰性页面光晕或背景；
- 成功、警告、危险或信息状态。

文本选择从前景文字和容器中性色推导，不使用 `colorPrimary`；选中文字保持正常高对比正文
颜色。状态色始终保留功能语义，并配合文字、图标或两者表达。

数据可视化使用独立的稳定分类色板，不借用 Action 或 Status 角色。图表的轴、标签、表面随
明暗模式切换，分类色则保持跨主题可辨认，避免同一个颜色在同一页面既表示状态又表示格式。
八种制品格式只有一份“格式 → Visualization 槽位”映射，图表、Badge 和公开目录标志共同
消费它；未知格式使用中性回退，不能临时借用状态色。

## 优先级与兼容

解析顺序固定为：

1. Ant Design 明暗算法生成完整 Token；
2. 主题包显式 Alias 精确覆盖派生 Alias；
3. 从完整 Token 推导 Console 语义角色；
4. 带类型的内置兼容覆盖保留有意设计的 Gateway Shell 特征；
5. Console 组件几何不变量与语义组件颜色生成最终 `ThemeConfig`；
6. 完整 CSS 变量投影原子应用。

每次投影都必须完整，因此反复切换主题不会残留上一套主题的值。Reduced Motion 继续跳过
空间动画，但最终颜色完全一致。

主题动效采用以触发器为锚点的 240 ms 径向揭幕：旧文档快照保持不透明，圆形裁剪从主题选择
按钮向外扩张并揭开新快照。浏览器不支持 View Transition 或用户启用 Reduced Motion 时，
同一次主题提交直接原子生效，不做逐后代元素的颜色补间。中性空状态使用小型语义图标与有效
文案，不再加载按主题区分的装饰插画。

## 迁移规则

- 自定义 CSS 只能消费语义 `--ag-*` 角色，不能读取 Ant Design 生成变量，也不能新增按主题
  ID 分支。
- 组件 CSS 新增颜色字面量时，必须说明它属于品牌资产，或先新增并评审语义角色。
- 应用组件不能使用 `text-cyan-*`、`bg-rose-*` 等色相工具类，也不能给 Ant Design 组件传
  `blue`、`green` 等预设色名；状态使用语义状态，分类使用 Visualization。
- 使用主色时必须能明确对应强调色预算中的允许目的。
- 现有通用 `brand`、`text`、`surface` 和状态别名迁移为明确角色名。
- 只有真实主题包无法由 v1 输入和确定性投影表达时才考虑 Theme Package schema v2；届时也
  只能增加小型白名单角色，不能接受任意变量表。

## 验收门禁

主题系统变更只有满足以下条件才算完成：

- 四套内置主题都能解析完整角色契约；
- 文本选择保持中性，且与主操作颜色明确不同；
- Ant Design 与自定义 CSS 在同一次主题提交中切换；
- 反复快速切换后没有旧变量残留；
- Lint、类型检查、单测、Ant Design 专项检查、格式和构建通过；
- 真实浏览器覆盖明暗、桌面/移动、键盘焦点、文本选择、快速切换和 Reduced Motion；
- 自定义扩展主题无需修改服务端 Schema 仍可使用。

## 影响

主题行为从选择器集合变成可测试的深模块。新增组件时必须先选择语义角色，这种摩擦用于
主动阻止强调色扩散。首屏调色板仍会重复两组回退值，但不再拥有独立行为，并受契约测试
约束。主题作者保留充分的颜色自由度，Console 则继续拥有层级、语义、可访问性和几何。
