# 原生管理架构与迁移边界

[English](0009-native-architecture.md) · [文档索引](../README.zh-CN.md)

状态：方向已接受；分阶段实现（#277、#285、#380）

## 背景与选项

管理适配器和聚合存储接口让迁移及格式开发跨越无关领域。保留 Nexus 别名、冻结管理
API 会延续这种耦合。比较两个方案：保持接口并机械拆文件，或允许管理接口发生破坏性
变化、逐领域迁移。依据 #380 选择后者。原生包协议继续遵循标准。

## 决策

- `cmd/gateway` 显式装配依赖；生产要求 PostgreSQL 与对象存储。领域服务消费窄接口。
- 管理 handler 按领域组织，负责 HTTP、鉴权与审计编排；生成的 OpenAPI 类型只在 HTTP
  边界使用。先改契约源，再在同一破坏性切片同步服务端、Console 和 agctl。
- 格式模块拥有坐标与线协议，可使用共享协议身份工具及领域接口，不依赖其他格式、
  HTTP 组合根或 PostgreSQL 实现。
- 领域记录和存储接口与 SQL 实现分离；实现进入 `internal/repository/postgres` 或领域
  `pgstore` 包（#282）。拆分前 `internal/repository` 仍混合持久化，本护栏不声称已完成
  SQL 隔离。
- memory 存储的去留由 #278 比较删除与共享契约测试，并测量 Raw tracer 后决定。
  本 ADR 不允许用近似实现替代事务、锁、租约或对象引用语义。

Nexus 管理 API、历史 Gateway 管理 API、认证模型和旧 URL 别名均不再是兼容要求。
现有别名直到对应实现切片移除前仍然存在，本决策本身不改变路由。删除操作、重新生成
客户端与消费方配置调整应在同一发行版本说明；无需维护双 API。数据库迁移仍只追加；
持久身份、摘要、授权、幂等、租约/fencing 与安全回收仍是要求。

## 迁移实施顺序

1. 先完成本 ADR 和依赖护栏（#277），决定测试存储（#278），再推进显式组合根（#279）、
   领域 handler（#280）、格式模块（#281）、持久化分离（#282）与 HTTP 横切能力（#283）。
2. 迁移工作遵守上述依赖，把 #269 拆为源发现/预检与显式映射、持久清单/断点（#205）、
   字节校验（#204）、Console 控制。涉及共享文件时顺序合入。
3. 借鉴 kkRepo [迁移指南](https://github.com/klboke/kkRepo/blob/main/docs/en/nexus-migration-guide.md)
   的元数据/字节分阶段与增量任务思路。Gateway 采用只读源发现、显式未支持结果和原生
   目标身份；源端脚本、凭据/hash 迁移及 URL 兼容均不是前置条件。#269 首期仍为 Maven
   release/Raw；OCI 闭包（#206）和 SNAPSHOT 继续独立验收。
4. 部署/切换前验证真实 Maven/OCI 消费者、最终库存与冷下载。#321 已由 #324 修复并随
   v0.8.1 发布；生产业务验收独立于已关闭的代码事项。源删除和生产路由另行执行。

## 可执行护栏与基线

`make architecture-check` 解析 `internal` 下全部非测试 Go 源码，包括当前 build tag
未启用的文件，并沿内部 import 图检查直接或间接依赖。协议模块新增对 `internal/app`、
PostgreSQL 实现及其他格式的依赖会失败。共享 `internal/protocol/identity` 不是格式。
现存违规按实际 import 边逐项记录于 `tools/architecture/baseline.json`，新增指向同一旧目标的依赖边仍会失败；解决后须在同一改动删除对应条目。
新增 `GatewayStore` 字段或方法按身份拦截，即使成员总数不增加也不能替换扩张；递归展开嵌入接口及别名，同时核对方法签名。
本地与 CI quality 都通过 `make lint` 执行。评审须拒绝扩大基线；它是债务记录，不能用于
批准新依赖。不提供自动重建白名单命令。

`make architecture-metrics` 输出可重复的 AST/源码指标。基线 `e9f53084`：app 生产文件
151 个、39,096 行；repository 生产文件 158 个、31,916 行；管理适配器方法 231 个；
聚合存储成员 49 个；app 中包含 `Format*` selector 的 switch case 140 个。
行数包含注释与空行、排除测试，不能与历史全文件统计直接比较。指标用于衡量进度，
不作为任意限制代码增长的阈值。

初始跨格式例外是混合 repository 包引用 Cargo 的实际依赖边（被 Conan、Maven、npm、
OCI、Raw 间接到达），由 #281/#282 消除。49 个嵌入接口当前展开为 436 个带声明接口
身份的方法签名。护栏覆盖源码依赖和聚合成员，不证明运行时
语义、不检查动态加载的依赖，也不能代替集成和真实客户端测试。
