# 管理 API 领域组合

[English](0012-management-domain-composition.md) · [文档索引](../README.zh-CN.md)

状态：已接受；通过 #280 按领域实施，从 #392 开始。

## 问题与方案

生成的管理接口描述全部操作，但旧适配器同时拥有全部依赖。只拆文件不能解除耦合。

1. 保留单适配器与统一聚合依赖：构造函数较少，但领域互相耦合，不能独立构造。
2. 用领域 handler 分别实现生成接口的不相交子集：各有明确构造函数与窄口，由一处编译期断言保证整个管理面完整。
3. 同时迁移所有 handler 到生成的 strict 接口：请求/响应类型化，但还要整体迁移流式上传/下载编排与错误产生方式。

选择方案 2。固定的生成器已经输出 strict-server 类型，生成这些类型不意味着必须使用。后续具体领域契约调整可以另行评估 strict 请求/响应适配；它不能代替领域依赖拆分，也不是 #280 的前置条件。

## 决策与落地

`managementServer` 通过嵌入组合领域 handler。每个领域独占所属操作，声明存储窄口，并有独立构造函数。生成的 `ServerInterface` 断言会拒绝缺失或重复方法。生成路由与参数绑定仍位于 HTTP 边界。本片不改变 OpenAPI、Console 或 agctl 行为，不引入第二套 API。

`managementScope` 只包含仓库查找、显式匿名策略读取、审计记录、认证、授权与拒绝计数；不持有 `GatewayStore`、身份存储、生命周期队列或格式存储。领域存储单独注入。匿名策略不再由仓库查找窄口的运行时具体类型隐式推断。

首个领域是仓库/Group 配置：仓库 CRUD 与能力、格式目录、Group CRUD/成员/容量/解析，以及仓库 egress probe。制品浏览、访问控制、身份、生命周期、运维、站点与 APT 在后续 PR 分别迁移。临时旧适配器只拥有尚未迁移的操作，最后一个领域迁出后删除，不作为兼容层保留。

## 制品发现与发布

第二片（#396）提取 `artifactManagementHandler`。目录查找、各格式搜索、browse、usage 与 identity 查询都有显式窄口。搜索不再从原生 Maven 发布器取得全量存储；usage 与 identity 能力在组合根识别并显式注入，缺失可选能力仍返回约定的 `not_supported`。原生 Maven/Conan 发布器继续负责对象流与事务发布，领域只接操作接口；Proxy 索引目录查询与 Maven 导航缓存也分别注入。

共享 Group 授权/解析只要求仓库查找；匿名策略读取只要求读方法，领域处理获准匿名 browse 时不需要策略写入能力。签名分页、仓库/主体范围、缓存与配置修订仍保持原语义。

## 验证与边界

只提供仓库/Group 窄口即可直接构造领域 handler，经生成的 HTTP 边界验证过滤、授权与拒绝审计、幂等、Group 成员校验及版本冲突。保留完整 Go 单测、覆盖率、lint、vet、OpenAPI 与文档门禁。

本次重构不改变持久化，也不迁移包协议 handler；不代表 SQL 包隔离（#282）、共享中间件收敛（#283）或生产验收已完成。
