本地运行容器与 GHCR 已发布镜像是不同证据对象。容器内使用校验过的发行包，运行基座按仓库 Dockerfile 的 digest 固定；本地 image ID 记录在证据 JSON 中。主线 CI 确认以下 manifest 已推送，但本机尚未成功拉取：

- Gateway：`ghcr.io/ccsert/artifact-gateway@sha256:22f1a0761ab457855ef43c35c35ff5edaca6e97e795e1f1a18bc8819d7e88df0`
- Console：`ghcr.io/ccsert/artifact-gateway-console@sha256:38c3b3a6270119d342ce532b9fd4d50fd9f5578c2acc85fed4e4d94c6181d376`

源码升级用例验证的是单 Proxy Maven 缓存和 Go Proxy 离线读取。新 Maven 策略仅在单候选时复用无 `resolution_scope` 的旧缓存；多个候选或范围变化可能需要重新解析和获取上游，Group 目录也只接纳当前范围的缓存证据。因此，本记录不承诺所有旧多成员 Group 在断网升级后都能沿用旧缓存。

## 阻断与后续

GHCR 匿名 token 请求返回 401，使用现有 GitHub OAuth 凭据拉取基线返回 `denied`；按候选 digest 拉取两个镜像均返回 `manifest unknown`。这些结果证明本机尚不能取得发布镜像；不能据此否定 CI 中已完成的推送，也不能把发行包容器当作发布镜像已验收。

完成具备该包读取权限的 GHCR 登录后，先解析并固定 `v0.1.0` 的 manifest digest，然后通过 `GATEWAY_UPGRADE_FROM_IMAGE` 和 `GATEWAY_READINESS_IMAGE` 指定发布镜像，重跑升级与恢复，并用发布的 Console 镜像复验登录和 Group 页面。完成后更新本记录和 #26。此阶段不创建正式 release tag，也不替代目标生产环境验收。
