# 在 Console 中首次发布 APT 快照

[English](apt-first-publication.md) | [文档索引](README.zh-CN.md)

Console 可以为 APT Hosted 仓库的空套件发布首个签名快照。这属于现有操作员预览，
不提供生产私钥托管、安装告警或自动分发可信公钥，也不代表完成
[#305](https://github.com/ccsert/artifact-gateway/issues/305) 跟踪的正式 Hosted 准入。

操作者需要仓库管理权限，Gateway 必须已配置 APT 发布服务及可信签名器，参见
[APT Hosted 签名](apt-hosted-signing.zh-CN.md)。没有仓库管理权限的普通用户不会请求
本页的管理员状态数据。

## 暂存、核对和发布

1. 打开仓库的 **APT 快照**任务，输入准确套件名，例如 `stable`，再点击**查看**。
   套件状态读取成功且没有快照历史或可见软件包时，才显示首次发布表单。
2. 选择一个非空 `.deb` 文件，大小不超过 1 GiB，并填写组件，例如 `main`。
   浏览器会计算文件的准确大小和 SHA-256；选择文件不会发出软件包上传或发布请求。
   请使用 HTTPS 或 localhost，以确保浏览器密码学功能可用。
3. 点击**暂存并核对软件包**。生成的管理 SDK 创建幂等发布会话，再将原始 File 作为
   Debian 软件包请求体直传。Gateway 校验字节并解析 control 元数据。
   暂存不会让 APT 客户端读到软件包。
4. 核对服务端报告的包名、版本、架构及规范身份，再勾选**已核对包名、版本和架构**。
   服务端 revision 的仓库、摘要或大小与所选文件不一致时，不允许发布。
5. 点击**确认并签署首次快照**，明确发布仅包含本次暂存会话的 `sequence: 1` 快照。
   成功后页面刷新当前快照，显示签名指纹、签名器等证据。

该表单不是已有快照的成员编辑器，不会递增 sequence，也不会把已有套件的部分成员
提交给全量发布 API。已有快照继续使用原有的预览确认生命周期、分发和归档操作。
若另一个请求并发完成了首次发布，仍由服务端的 sequence 和幂等检查决定结果，
本表单不会覆盖它。

## 失败与重试

校验、配额、签名或网络失败后，文件选择、组件、会话及已确认的暂存身份均保留在内存。
请求开始后，文件、组件、请求体和幂等 key 保持不变。创建会话响应丢失时重放同一个
创建请求；上传重试使用同一个会话和原始 File；发布重试使用相同 key、会话及 sequence。
请求执行期间阻止重复提交。

签名器返回 `503` 后保留已暂存软件包，可直接重试。发布响应丢失不会被视为成功，
必须重试同一个发布请求。发布已明确成功但刷新失败时，不会重新启用发布；请使用
**刷新快照**重新读取已确认的当前快照。

修改文件或组件前，需要明确点击**清除本次选择**并确认。已上传的暂存数据由服务端
过期回收，清除表单不会将其发布。文件和重试 key 不写入浏览器存储、URL 或共享查询缓存。
切换仓库或套件、重新加载页面会丢弃本地草稿；旧目标的响应不能填入或发布新目标的表单。

## 验收边界

Console 回归使用固定的合成 `.deb`、真实浏览器 SHA-256，以及生成 SDK 的实际 HTTP
序列化。合成 API 回应覆盖暂存、签名拒绝、已提交后丢失响应、精确重试和双语桌面/窄屏布局。
这些浏览器夹具不证明真实签名器、PostgreSQL 事务、对象存储或 APT 安装；真实后端及
原生客户端流程由独立的 [APT Hosted 分发门禁](apt-hosted-distribution.zh-CN.md) 验证。
两类证据均不代表生产密钥托管或正式准入。
