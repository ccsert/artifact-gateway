# 旧 Group 迁移

[English](legacy-group-migration.md) · [文档索引](README.zh-CN.md)

旧 OCI、Maven、Raw 与 Conan Group 继续作为协议专属兼容入口，不会被原地改写。迁移时
创建由明确 Hosted 和 Proxy 仓库组成的 V2 Group，完成验证后再切换客户端。

## 步骤

1. 盘点旧 Group 的有序成员、上游地址、主机允许列表、匿名设置和消费者 URL。
2. 为每个成员创建一个 V2 Hosted 或 Proxy 仓库，保留格式、Endpoint、允许主机和仓库
   专属授权。
3. 创建相同格式和成员顺序的 V2 Group。所有成员都通过 `repositoryId` 绑定；托管授权
   检查要求显式绑定。
4. 验证认证读取期间保持匿名访问关闭。确需公开读取时，有意识地同时开启全局策略、
   Group 策略和每个成员仓库策略。
5. 对比新旧入口的协议读取、缓存行为、审计记录和成员顺序。全部通过后再切换客户端 URL。
6. 所有客户端完成迁移前保留旧 Group。删除 V2 Group 不会删除成员仓库或制品字节。

## 边界

- V2 Group 是有序视图，不拥有制品或缓存字节。
- 容量按成员贡献报告，不算作 Group 自有存储。
- 仓库授权适用于显式绑定的 V2 成员。未绑定旧成员在迁移前仍遵循旧静态策略。
- 不要通过复制缓存对象或修改旧 Group 数据行迁移。Proxy 缓存会随客户端读取自然预热，
  孤儿对象由正常调度的回收任务处理。
