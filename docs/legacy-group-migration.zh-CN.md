# 旧 Group 迁移

[English](legacy-group-migration.md) · [文档索引](README.zh-CN.md)

旧 OCI、Maven、Raw 与 Conan Group 继续作为协议专属兼容入口，不会被原地改写。迁移时
创建由明确 Hosted 和 Proxy 仓库组成的 V2 Group，完成验证后再切换客户端。

## 步骤

1. 盘点旧 Group 的有序成员、上游地址、主机允许列表、匿名设置和消费者 URL。
2. 为每个成员创建一个 V2 Hosted 或 Proxy 仓库，保留格式、Endpoint、允许主机和仓库
   专属授权。
3. 创建相同格式和成员顺序的 V2 Group。所有成员都通过 `repositoryId` 绑定；托管授权
   检查要求显式绑定。
4. 验证认证读取期间保持匿名访问关闭。确需公开读取时，有意识地同时开启全局策略、
   Group 策略和每个成员仓库策略。
5. 对比新旧入口的协议读取、缓存行为、审计记录和成员顺序。全部通过后再切换客户端 URL。
6. 所有客户端完成迁移前保留旧 Group。删除 V2 Group 不会删除成员仓库或制品字节。

## 边界

### Maven 解析与缓存兼容

Maven V2 Group 先尝试全部 Hosted，再按配置顺序尝试符合条件的 Proxy。GET、HEAD 在
Proxy 返回 404 后继续下一个成员。沿用 Maven 原有重试和失败策略：上游故障时可以回退
到后续成员，但仍有未解决故障的请求不会生成表示整个 Group 缺失的负缓存。

新的正负缓存携带带版本的解析范围摘要，绑定有序授权候选、仓库 ID、上游、允许列表、
匿名资格和出口代理配置。每次缓存读取仍检查来源成员；范围变化会使索引失效并重新解析，
不可变字节继续遵循正常回收流程。较早成员故障或代理被拒绝后的成功回退只服务当前请求，
不缓存为聚合结果，使恢复后的较早成员能重新获得优先级。

旧的无范围缓存，仅在实际只剩一个获授权 Proxy 且允许的来源匹配时继续使用。它不能证明
多成员 Group 的解析结果，首次读取时会刷新。PostgreSQL JSON 索引可直接保留范围字段，
无需 Schema 迁移；缓存键和管理失效入口保持稳定。相同候选的读取者可以共享缓存，授权
或匿名资格变化后则按新的候选重新解析。

`make native-maven-e2e` 验证 Maven release 和 Gradle SNAPSHOT 通过双 Proxy Group
读取，其中首上游固定返回 404，同时覆盖 metadata 和 checksum sidecar。HTTP 与
PostgreSQL 测试覆盖旧缓存兼容、候选变化、Range/条件读取、故障恢复及授权隔离。

### 所有权与迁移

- V2 Group 是有序视图，不拥有制品或缓存字节。
- 容量按成员贡献报告，不算作 Group 自有存储。
- 仓库授权适用于显式绑定的 V2 成员。未绑定旧成员在迁移前仍遵循旧静态策略。
- 不要通过复制缓存对象或修改旧 Group 数据行迁移。Proxy 缓存会随客户端读取自然预热，
  孤儿对象由正常调度的回收任务处理。
